# BioCode-Web-UI 前端项目架构规范

本项目采用 **SOA 架构**，按业务领域分类组织代码。
本文档同时是项目对 AI 与新成员的硬性约束，**不论 AI 还是人类，必须严格遵守**。

---

## 一、目录结构

```
src/
├── soa/                        # 全局 SOA 服务（跨业务复用）
│   ├── com-series/             # COM 系列 - 含业务逻辑的通用组件（框架、菜单、Tab、登录等）
│   ├── std-series/             # STD 系列 - 不含业务逻辑的标准化组件（列表布局、查询区、控件等）
│   ├── genric-route/           # 通用路由服务（GenricRouteRegister / GenricRouteService）
│   └── template/               # 新业务域模板（创建新域时复制这里）
│
├── views/                      # 业务模块（按领域划分，与后端 biz 域一一对应）
│   ├── core/                   # 核心域（用户、组织、菜单、注册表、附件、通知…）
│   ├── auth/                   # 认证授权域
│   ├── audit/                  # 审计域
│   ├── relay/                  # 中继服务域
│   ├── rdbg/                   # 请求调试域
│   ├── document/               # 请求文档域
│   ├── drive/                  # 网盘域
│   ├── qf/                     # 轻工作流域
│   ├── qt/                     # 轻任务调度域
│   └── assembly/               # 装配/代码生成域
│
├── commons/                    # 公共底座（HTTP、Result、PageResult、工具函数、模型）
│   ├── Http.ts                 # 全局 axios 封装，所有请求必须经过它
│   ├── model/                  # 公共数据模型（Result / PageQuery / PageResult / 共享 JSON 模型）
│   └── service/                # 公共服务（QueryPersist / Hotkey / ContentType / FileCategory…）
│
├── styles/                     # 全局样式与 Element Plus 主题覆盖
└── AdminMain.ts                # 应用入口
```

---

## 二、业务模块（views/xxx/）内部结构

每个业务模块包含以下目录：

| 目录             | 职责                                                         |
| ---------------- | ------------------------------------------------------------ |
| **api/**         | 接口请求方法、DTO/VO/PO 类型定义                             |
| **components/**  | 业务组件，只负责渲染                                         |
| **service/**     | 业务逻辑、状态管理、复杂交互编排                             |
| **route/**       | 该域的路由注册器（`XxxRouteRegister.ts`），通过 GRS 显式注册 |
| **sfc_private/** | 仅供本模块入口页内部使用的私有 .vue / .ts，不允许跨模块引用  |
| **入口文件**     | 如 `Drive.vue`、`QfModel.vue`，组装 Service 与 Components    |

**禁止**直接跨域引用其他业务模块的 `service/` 与 `components/`。
跨域复用的代码必须下沉到 `soa/` 或 `commons/`。

---

## 三、SOA 三大子系统

| 子系统                   | 定位                                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------------------------- |
| **COM 系列(有业务组件)** | 通用业务组件：框架、菜单、Tab、用户档案、导入向导、CronFixer、SeqFixer、滑动验证码                    |
| **STD 系列(无业务组件)** | 标准化无业务组件：StdListLayout / StdListContainer / StdQueryCollapse / StdTimeRange / StdIconPicker… |
| **GenricRoute(GR模块)**  | 整个项目的跨域路由统一注册与跳转                                                                      |

> **关键原则**：业务页统一通过 `StdListLayout` + `StdListAreaQuery` + `StdListAreaTable` + `StdListAreaAction` 组装，  
> 不允许业务页直接堆叠重新发明轮子。

---

## 四、命名规范

| 类型     | 规范                  | 示例                                           |
| -------- | --------------------- | ---------------------------------------------- |
| 文件夹   | kebab-case            | `com-series`、`std-series`、`genric-route`     |
| Vue 组件 | PascalCase            | `DriveEntryGrid.vue`、`StdListLayout.vue`      |
| TS 文件  | PascalCase            | `DriveService.ts`、`DriveApi.ts`               |
| 路由注册 | `XxxRouteRegister.ts` | `AuthRouteRegister.ts`、`CoreRouteRegister.ts` |
| 函数命名 | `onXxx` / `doXxx`     | 事件用 `onXxx`，禁止 `handleXxx`               |
| 导入路径 | `@/` 绝对路径         | 禁止使用 `../../../` 之类的相对路径            |

---

## 五、路由

- 路由 **必须** 通过 `GenricRouteRegister.register({...})` 显式注册。
- 路由声明集中在每个域的 `route/XxxRouteRegister.ts` 文件内，便于搜索与权限审计。
- **禁止** 引入文件系统自动路由（unplugin-vue-router 类）。

---

## 六、HTTP

- 所有接口请求必须经过 `commons/Http.ts`，禁止直接使用裸 axios。
- DTO/VO/PO 类型定义放在每个域的 `api/` 目录，命名与后端保持一致。
- 列表分页接口统一使用 `commons/model/PageQuery.ts` 与 `commons/model/PageResult.ts` / `RestPageableView.ts`。

---

## 七、状态与持久化

- 状态管理统一使用 **Pinia**。
- 需要持久化的状态使用 **pinia-plugin-persistedstate**。
- "查询持久化"功能由 `commons/service/QueryPersistService.ts` 统一处理。
- **禁止** 引入 localforage、mitt、自建 EventBus 等替代方案。

---

## 八、样式

- 全局主题与 Element Plus 覆盖样式集中在 `src/styles/`。
- 工具类样式使用 **Tailwind CSS 4**（class 形式），复杂样式使用 **SCSS**。
- **禁止**使用属性化样式写法（如 `bg="dark:[var(--el-bg-color)]"`、`h-full w-full flex flex-col` 满天飞）。
- **禁止** 引入 UnoCSS。

---

## 九、禁止引入的技术

| 类别         | 禁止项              | 理由                        |
| ------------ | ------------------- | --------------------------- |
| 文件系统路由 | unplugin-vue-router | 已有GRS服务，引入会打架     |
| 属性化样式   | UnoCSS attributify  | 样式与模板混杂、AI 难以阅读 |
| 状态广播     | mitt、自建 EventBus | 已有 Pinia + SOA服务化方案  |
| 本地存储     | localforage         | 已有 pinia-persistedstate   |

### 9.1 引入新依赖的硬性条件

新依赖（含 dependency / devDependency）必须同时满足：

1. GitHub 近 12 个月有持续提交。
2. 维护者数量 ≥ 2 或属于知名组织。
3. 有真实业务场景需求，不为单一函数全量引入。
4. 与现有方案不构成功能重复。
5. **AI 严禁未经审核擅自添加依赖**，违反者拔电源。

## 十、TypeScript

- 严格模式当前为分级开启状态，**新建模块鼓励开启 strict**。
- 业务模型类型（DTO/VO/PO）必须在 `api/` 目录显式定义，禁止使用 `any` 蒙混过关。
- 所有 import 使用 `@/` 别名，**禁止相对路径导入**（已由 ESLint 规则强制）。
- 严禁多个接口共用同一个类型或新增、编辑等合用类型，应分别定义类型并与后端对齐(Dto/Vo)！，绝对不要使用partial、omit、pick缝合类型。

---

## 十一、单页代码体量

- 业务 `.vue` 单文件 **超过 400 行** 应触发审视：
  - 是否可下沉到 `service/`？
  - 是否可拆分为 `components/` 子组件？
  - 是否抽象层使用不当（应该用 Std 系列却堆原生 Element Plus）？
- **禁止** 在业务页面内部直接维护 10 个以上 dialog / modal 状态而不抽象。

---

## 十二、AI 编码守则

1. **不擅自加依赖**。
2. **不绕开 Std/Com 抽象**直接堆原生组件。
3. **不写 `handleXxx`**，事件命名一律 `onXxx`。
4. **不用相对路径导入**，统一 `@/`。
5. **不引入魔法栈**（auto-import / file-based router / attributify css）。
6. **不在业务域之间互相 import**，跨域复用必须经过 `soa/` 或 `commons/`或`public/`。

---

## 十三、新建业务域流程

1. 复制 `soa/template/` 为模板(现在可以使用QBE代码生成器，不需要用到手动模板)。
2. 在 `views/` 下创建新域目录（与后端 biz 域同名）。
3. 创建 `api/` `service/` `components/` `route/` `public/` 子目录。
4. 编写 `XxxRouteRegister.ts` 并在 `AdminMain.ts` 中注册。
5. 列表页统一使用 `StdListLayout` 系列组装。
6. 提交前确保 `pnpm lint` + `pnpm type-check` 通过。
